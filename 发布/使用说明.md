# 随机抽人

随机抽取一名学生，抽中后自动从抽取池移除，不会重复抽到同一人。
面向课堂点名、答辩抽签等场景，约 200 人规模。

## 两种版本

| | 桌面版 `随机抽人.exe` | 网页版 `随机抽人(网页版).html` |
|---|---|---|
| 使用方式 | 双击 exe，弹出独立窗口 | 双击 html，用浏览器打开 |
| 体积 | 19 MB | 68 KB |
| 数据存放 | exe 同目录的 `data.db` 文件 | 浏览器本地存储 |
| 导入 Excel | `.xlsx` / `.xls` / `.csv` | `.xlsx` / `.csv`（读不了 `.xls`） |
| 批量导入多文件 | 支持 | 支持 |
| 首次打开 | 可能弹出 SmartScreen 提示，见下文 | 无任何提示 |
| 适合 | 自己长期使用、需要导入 Excel | 发给别人演示、U 盘随身携带 |

两个版本功能一致，数据各自独立，互不影响。

## 快速开始

**桌面版**：把 `随机抽人.exe` 放到任意文件夹（例如桌面新建一个「抽人」文件夹），双击打开。
第一次启动需要解压，约 2–4 秒，请稍等。

**网页版**：直接双击 `随机抽人(网页版).html`，用 Edge 或 Chrome 打开即可。
已内置 210 人示例名单，打开就能抽。

## 首次打开 exe 时的蓝色提示

因为没有代码签名证书，Windows 第一次运行时会弹出蓝色窗口：
**「Windows 已保护你的电脑」**。这不是病毒提示，是所有未签名程序的通用提示。

处理方法：点左侧的 **「更多信息」**，再点 **「仍要运行」**。之后不会再提示。

> 可以直接把下面这段话转发给接收方：
>
> 这个程序没有购买数字签名，Windows 首次运行会提示「已保护你的电脑」，
> 点「更多信息」→「仍要运行」即可，是正常现象。
> 程序不联网、不收集任何数据，所有记录只存在本机。

## 功能

**抽取**：点「开 始 抽 取」或按空格/回车。名字滚动约 1 秒后定格，抽中者立即从池中移除。
大屏同时显示这次抽取的日期和学号班级——200 人里可能有同名同学，靠学号班级区分；
没抽取时大屏显示今天的日期。

**课表联动**：抽取池会排除**此刻有课**的同学。判定规则：

```
不可用 = 现在落在某个「该生有课的」大课区间内
        OR 距下一个「该生有课的大课」开始不足 N 分钟（默认 30，可改）
        OR 本学期已谈过
        OR 已停用
```

一天四个大课（上午两节、下午两节），大课区间含中间那 10 分钟课间，
所以**课间也算上课期间**；20 分钟大课间如果后面还有课，因为不够谈话时间，同样算不可用。
顶栏的「此刻可抽」会随时间变化，下方同时给出构成（未谈多少、多少人在上课），
一个人都抽不出来时会写明原因和下一段空闲时间。

**按教学周判断**：时段可以是「只有某些周有课」。在「课表」页填写**第 1 周从哪天开始**
（第 1 周的周一），程序就能算出现在是第几周，顶栏会显示「第 N 周」。
课表的周次支持 `1-16`、`1-8,10-16`、`1,3,5`、`单`、`双`，留空表示每周都有课。
**没填学期开始日期时**，用了周次的时段会按「每周有课」保守处理（宁可少抽一个，
也不要抽到正在上课的人），界面会明确提示这一点。

课表按**班级**录（同班课程一样），个别同学有选修课的用「个别学生例外」单独加
（例外暂不区分周次，整学期生效）。
课表可以直接导入 **`.xlsx` 或 `.csv`**（两种格式都支持；`xls` 旧格式需先另存为 xlsx）。
导入格式是一行一个课时：`班级,星期,大课,周次,课程`，其中星期可写 `3` 或 `周三`，
大课可写 `1` 或 `上午第一节大课` 或简写 `上①/下②`，周次可写 `1-8,10-16`、
`单`/`双` 或留空（每周）；班级写成 `@姓名` 的行会被当作该学生的个别例外。
旧的 4 列格式 `班级,星期,大课,课程` 仍然可用（周次视为每周）。导入是**合并**而非覆盖，不会清掉已录的课表。
多工作表时按「能解析出的课时数」自动挑表，封面页/名单页在前也能挑对。

没录课表时**不会排除任何人**，行为和以前完全一样。

**开始新学期**：所有人回到抽取池，本学期记录归档保留。（等价于原来的「重置本轮」，
只是因为谈话记录按学期累计，叫「学期」更贴合。）

**抽取历史**：右侧**按日期分组**，每天一个标题（今天 / 昨天 / 9月17日 周三），
同一天内按抽取先后列出，组标题右侧显示当天抽了几人。标题栏还会提示
「今天已抽 N 人」或「今天还没抽」。

**撤回**：把抽错的人放回池子（比如抽到的同学临时来不了，要换一个人），
撤回后序号会自动重排，不会留下空缺。

**重置本轮**：所有人回到抽取池，历史保留，轮次 +1。
适合「这节课抽完一轮，下节课重新开始」。

**名单管理**：
- **勾选后批量操作**：每行左侧有勾选框，表头可全选（只作用于当前搜索筛选出的行）；
  勾选后出现操作条，可一次**停用 / 启用 / 删除**多人，不必一个个点
- 直接点表格里的姓名/学号/班级即可修改，失去焦点自动保存
- 停用：暂时不参与抽取（请假、转走），**重置本轮也不会把他放回池子**
- 删除：从名单彻底移除（历史记录仍保留姓名，不会变成空白）
- 导入名单 / 粘贴文本导入 / 新增学生
- 导出备份、导入备份、清空名单

**批量导入**：名单和课表都支持**一次选多个文件**（按住 Ctrl 多选）。
提示会汇总成「已导入 3 个文件，共 620 人」，每个文件的成败单独列出；
某个文件坏了只报它一个，不影响其他文件。

**导出记录**：导出为 CSV，**日期和时间分成两列**，方便按天统计；
带 UTF-8 BOM，Excel 双击打开不乱码、列自动对齐。导出的是全部轮次的完整记录。

**界面**：浅色主题，字号分五级（品牌/分区标题/正文/辅助/极小），
按钮按重要性分三档（主操作金色大按钮、次要操作小号描边、危险操作小号红字）。
课表页把「操作」和「设置」分成两块：第一行是导入/导出/清空，第二行是一张设置卡片
（学期开始日期、最短可谈时长、保存设置）。抽取页的大字保持高对比，方便投影。

## 导入名单的格式

支持两种：

1. **有表头**（推荐）：能识别 `姓名` `学号` `班级` 等列名，列的先后顺序随意

   ```
   姓名,学号,班级
   张三,2024240101,计算机2401
   李四,2024240102,计算机2401
   ```

2. **无表头**：默认按「姓名,学号,班级」解析；若首列全是 6 位以上数字，
   会自动识别为「学号,姓名,班级」

其他细节：
- 只粘姓名也行，一行一个，能自动去掉「1. 张三」这类行首序号
- Excel 的 `.xlsx` 两个版本都能直接导入；首行若是「XX班学生名单」这类标题也能自动跳过，
  第一张工作表是封面页时会自动选到真正的名单表
- 逗号、制表符、分号分隔都能识别
- 中文 Windows 上 Excel 另存的 GBK 编码 CSV 也能正确读取
- 完全重复的条目会自动跳过；**同名不同学号会全部保留**并给出提示

网页版能直接读 `.xlsx` 是因为内置了一个用浏览器原生能力实现的解析器
（`DecompressionStream` 解压 + `DOMParser` 解析 XML），不依赖任何外部库，
所以依然保持单文件离线可用。两种版本的解析规则一致。
旧版 `.xls` 格式两个版本都不支持，请在 Excel 里另存为 `.xlsx`。

## 数据在哪、怎么备份

- **桌面版**：`data.db` 在 exe 同目录（若该目录不可写，会自动改存 `%APPDATA%\随机抽人\`）。
  整个文件夹拷走就是完整迁移。
- **网页版**：数据在浏览器本地存储里。**清理浏览器数据会丢失**，请用「导出备份」定期存档，
  换电脑后用「导入备份」恢复。

抽取记录也会导出成 CSV，可用于统计发言次数等。

## 常见问题

**双击 exe 没反应？** 首次启动需要解压，等 2–4 秒。若仍未出现，检查任务栏是否已最小化。
桌面版启动异常时会自动改用浏览器模式，可以用 `随机抽人.exe --http` 手动触发。

**抽过的人又出现了？** 只有在点了「重置本轮」之后才会。重置的设计就是让所有人重新参与。

**想换一批人重新开始？** 「名单管理」→「清空名单」，再导入新名单。
若只是想重新抽，用「重置本轮」。

**教务导出的 `.xls` 打不开？** 桌面版支持 `.xls`（教务系统导出的一般是这种旧格式），
网页版读不了——那是二进制格式，浏览器里实现代价太大。网页版遇到 `.xls` 会明确提示用桌面版。

**网页版导入 Excel 没反应？** 网页版的 xlsx 解析依赖浏览器的 `DecompressionStream`，
Edge / Chrome 2021 年以后的版本都支持。若浏览器过旧会给出明确提示，
此时在 Excel 里「另存为」选择 **CSV UTF-8(逗号分隔)** 再导入即可。

**浏览器清理后网页版数据没了？** 网页版依赖浏览器存储。平时用「导出备份」，
需要时「导入备份」恢复。想要更稳的持久化就用桌面版。

### 设计要点

**「删除」用标记实现，不是物理删行。** 抽中即置 `drawn=1` 移出抽取池，
对使用者的可见行为与删除完全一致，但保留了撤回、重置、导出记录的能力。
名单管理页另提供真正的永久删除。

**两个独立状态位。** `enabled`（是否参与抽取）与 `drawn`（是否已被抽出）必须分开：
若共用一个字段，「重置本轮」会把请假被停用的学生错误地放回池子。

**抽取用 `secrets.choice` / `crypto.getRandomValues`** 配合拒绝采样，无模偏差。

**抽取是一个事务。** 选人、移出池子、写记录三步在同一个事务内完成，
不会出现「人已移出但记录没写」的状态；动画只负责揭晓，结果在点击瞬间已落库。

**历史表冗余存姓名快照**，因此永久删除学生后，历史记录和导出的 CSV 仍完整。

**界面通过 `call()` 适配层调用后端**，`index.html` 里 `BEGIN/END ADAPTER` 之间的
这一小段可整体替换，三种后端（pywebview 桥 / HTTP fetch / 纯 JS）共用同一套界面与样式。

**改 `index.html` 的 CSS 时注意选择器优先级。** `#view-draw` / `#view-roster` 用
ID 选择器设了 `display`（优先级 1,0,0），会压过 `.view[hidden]`（0,2,0），
于是 `hidden` 属性对它们失效、页面切不动、名单管理页被挤到视口外面点不到。
必须保留 `#view-draw[hidden], #view-roster[hidden] { display: none; }`。

**文件对话框的过滤器字符串有格式限制。** pywebview 用
`^([\w ]+)\(...\)$` 校验，描述部分只允许字母、数字、下划线、空格，
写 `Excel / CSV (*.xlsx;*.csv)` 会因为斜杠被判非法，`create_file_dialog`
直接抛 ValueError、对话框打不开。改动 `app.py` 顶部的 `FILTER_*` 常量后，
务必跑 `tests/test_app_api.py`——那里用 pywebview 自己的解析函数逐个校验。

**断言界面正确性时要测可见性和坐标，不能只数元素个数。** 上面那个 CSS bug 靠
`document.querySelectorAll("#roster-body tr").length` 是查不出来的——元素在 DOM 里
就数得到，跟它可不可见、能不能点到无关。`tests/check_layout.py` 用
`getComputedStyle` 判可见、用 `getBoundingClientRect` 判是否在视口内、
用 `elementFromPoint` 判是否真能被点中，这三样才拦得住。

**不要把异常吞掉当作「用户取消」。** `_pick_open_file` / `_pick_save_file`
返回 `(路径, 错误)` 二元组：`None` 才表示取消，错误字符串表示对话框本身失败。
合并这两者会让对话框故障表现成「点了按钮没反应」，无从排查。

**`Api` 的数据属性必须用下划线开头（`self._conn` / `self._window` 等），不要改成公开名。**
pywebview 启动时会用 `util.get_functions()` 递归遍历 `js_api` 对象的每个公开属性
（下划线开头的会被跳过），遇到非可调用对象就继续往里递归。曾经把窗口对象存成公开的
`self.window`，于是它顺着 `window.native` 走进 WinForms/COM 对象图，出现
`AccessibilityObject.Bounds.Empty.Empty.Empty...` 无限递归，并大量触发跨线程 COM 调用，
导致**启动时窗口「未响应」、日志刷屏几千行**。改成下划线开头后，启动从卡死变成
1.5 秒进入响应、报错 0 行。只有需要暴露给界面调用的方法才用公开名字。

**课表按「大课」而不是小节**。学校课程以整个大课为单位排课（不存在只上一小节的情况），
所以 `blocks` 表只记 4 个大课的起止时间，`schedule` 按 班级×星期×大课 记有无课。
判定只需「现在是否落在某个有课的区间内」+「距下个有课的大课够不够时间」两件事。

**没录课表时不能排除任何人**。这是兼容性底线：`schedule_configured()` 为假时
完全跳过课表判定，否则用户还没录课表就会发现一个人都抽不出来。有测试专门锁这条。

**课表查询必须按星期过滤**。曾漏掉 `WHERE weekday=?`，导致周三录的课表在周四、
周六也生效，整个星期维度失效——写查询时注意。

**个别学生例外的 `has_class=0` 是有意义的信息**，不能像班级课表那样「取消就删行」：
它表示「全班有课但这个学生不上」。取消例外要用 `clear_exception()`。
班级课表则相反：取消勾选且无备注就删行，保持数据干净。

**学期计数复用 `round` 字段**。它本来就是「一个可重置的批次」，语义与学期一致，
因此不需要改数据库结构；界面文案统一叫「学期」，内部字段名保留 `round`。

**启动时要容忍 JS 桥迟到。** pywebview 是页面加载之后才注入桥的，冷启动偏慢时
（onefile 首次解压、机器较慢）桥会晚到几秒。`resolveShell()` 的检查顺序是
「先看桥在不在 → 再信缓存的外壳类型」，`call()` 在桥未就绪时会先等再试，
`boot()` 失败会重试 4 次。这套逻辑由 `tests/check_late_bridge.py` 覆盖，
去掉任何一环都会让界面卡在「无法连接后端」。
